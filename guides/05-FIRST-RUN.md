# 05 — 第一次运行

## 1. 先确认这是一个新 session

新 session 应该是：

```text
没有本地 bc-index.jsonl
A/C/K 空
```

为什么强调这个？

因为很多人会把“新 session 空表”误认为“插件没工作”。

**比如这种情况：**

```text
如果 session 是新的，A 空、B 空，
则这是正确起点，不是故障。
```

## 2. 安装并重启

安装 tgz，重启 DSH，确认版本。

```text
dsh-continuity-4.9.129-safe.1.tgz
```

**比如这种情况：**

```text
如果只复制了文件没有重启，
则版本号和面板都可能是旧的。
```

## 3. 第一次启动应该看到什么

```text
sessions/<id>/ 出现基础文件
rules.md / habits.md 来自 templates/
第一次 pre-step 后出现 bc-index.jsonl
左侧“连续性”出现
右侧“更多工具”出现 A/B/C/K
```

如果左侧没有“连续性”：

```text
不是表空，是 client 没加载。
```

如果右侧没有 A/B/C/K：

```text
不是表空，是宿主缺少 sidebarRight 或 tab 注册失败。
```

如果 tab 打开是空表：

```text
正常，继续往下看。
```

## 4. 空表阶段

```text
A 空 -> B 空
C 空 -> 没有 C 命中
K 空 -> 没有 K 命中
```

这不是“什么都没发生”。  
索引已经在积累，只是还没有概念。

**比如这种情况：**

```text
如果 A 一直是空，
则 B 也一直是空，
即使已经聊了 500 轮。
```

因为 B 不是从对话自动生成，而是用 A 给对话打分。

## 5. 前 200 轮做什么

```text
正常聊天
需要回忆时用 recall(query)
重要结论写进本 session 的 files 或工作区 log
```

不要做的：

```text
不要等系统自动生成 A
不要复制别的 session 的 A
不要为了“有表”而编概念
```

**比如这种情况：**

```text
如果前 200 轮一直在聊，但 A 从未写，
则第一次审计也可能因为没有 A 而跳过。
```

这是当前设计的一个坑，4.9.112 起 rules 已明确要求维护 A，但已有 session 不会自动改 rules。

## 6. 第一次写 A

当聊天里出现一个稳定、反复出现的话题：

```text
在 sessions/<id>/concepts.md 追加一行：
名字 | 描述词 | 参考覆盖 | kind
```

例子：

```text
示例主题 | 项目、决定、复盘 | 5 | topic
```

不需要一次写很多。  
先写一条，观察 B 是否开始有区分度。

**比如这种情况：**

```text
如果 A 只有一条“工作”，
则 B 会把很多不同话题都打成“工作”，
看起来有标签，其实没有区分。
```

## 7. 第一次审计

到 200 轮左右，可能出现：

```text
[continuity:audit]
```

但它不是必然出现：

```text
A 空 -> 跳过
没有 vec -> 可能跳过
没有明显未决簇 -> 没有候选
```

**比如这种情况：**

```text
如果 200 轮到了但没有审计，
不要立刻认为审计坏了；
先看 A 是否为空、index 是否有 vec。
```

## 8. 第一次重建

如果 session 已经有很长的历史，但 A/B/C/K 一直空：

```text
不要从当前轮开始补
直接读 04-REBUILD.md
```

**比如这种情况：**

```text
如果已经聊了 507 轮，A 还是空，
则从第 508 轮开始写 A，只能覆盖以后，
前 507 轮仍然没有 B。
```

需要 rebuild + relabel 历史。

## 9. 验收

```text
A/B/C/K 文件存在且只属于本 session
recall 使用本 session 的索引
B 对至少部分轮次有标签
没有改到别的 session
没有新的 gate-errors
```

如果这些都对，第一次运行才算完成。
